# Changelog

## Unreleased

### App
- **The whole interface has been rebuilt on one design system.** The app was shipping two brand colours and two greys at the same time: buttons, dropdowns and the date picker rendered blue-on-slate while every hand-written accent was indigo-on-zinc, which in dark mode showed as a visible navy-against-charcoal seam between the sidebar and the content. Colours, type sizes, corner radii and shadows now come from one place, so light and dark stay in step.
- **A board card reads as a title.** The first thing on every card used to be its ticket number, with the title on line two and the description underneath — so a card carrying a spec rendered as a paragraph, and a column of twenty read as a wall of identifiers. Titles come first and are capped at two lines, tags are an outlined pill rather than a filled uppercase one — as many as fit on the line, then a count of the rest, instead of a fixed two — and the ticket ID sits on a quiet footer line where it is still one click to copy. Priority is a thin coloured edge, and only High and Urgent get one, so an urgent card actually stands out. Cards fit their content instead of always reserving a footer row, assignees show their picture rather than initials, and the "N/A" badge on unassigned cards is gone.
- **Lists can show comment and attachment counts,** as sortable columns — so "what is being argued about" is a click on a header rather than a read of every row. Add them under view settings → Columns; a card with none shows nothing rather than a zero.
- **A card says how much discussion it has had.** The footer counted attachments and not comments, which is the wrong one of the two to have: an attachment is usually a screenshot pasted once, while three comments mean the card is being argued about — the thing you scan a board to find. Both counts show only when there is something to count.
- **Boards choose what their cards show.** View settings → Display lists the eight things a card can display — description, tags, ticket ID, comment and attachment counts, assignee, due date, priority — and any of them can be switched off for a board that doesn't want them. All on by default. A list view has always let you pick which fields a row shows; this is the same choice for a board. **Hiding a field never takes away the field:** the card's footer row stays, so tags, priority, due date and assignee are still there to set when you hover, and a hidden one still names its current value in the tooltip. Turning something off makes a board quieter, never harder to use.
- **You can set a due date and change tags from a board card.** Both used to appear only when they already had a value, so the one card that needed a date was the one card that couldn't be given one without opening it. Every card now has the same four controls in the same four places — tags, priority, due date, assignee — all four quiet until you reach for them, each naming itself and its current value when you point at one. The card face keeps the readouts it always had, so nothing is said twice: the tag row, the coloured priority edge, the assignee's picture, the date itself. "Open in full page" moved up beside the title, since it's the one control that leaves the board rather than changing the card. Nothing extra shows on a card at rest.
- **You can add a card by typing.** "Quick add", at the foot of a column, opens a one-line box instead of the full card dialog, and stays open so you can type a backlog in one go. The `+` in the column header opens the full dialog with that column already chosen — the same "New card" as the toolbar, which until now always dropped the card in the first column. The two used to do the same thing from opposite ends of the column, neither of them saying which. The `…` menu beside the `+` is gone too: it offered that same add action a click further away, plus the board settings that are already in the view header.
- **Dragging a card shows where it will land.** The target column lights up, empty columns offer a proper drop area, and the board fades at the edges when there are more columns off-screen.
- **Cards open in a side panel.** Clicking a card slides a panel in from the right instead of covering the board with a centred dialog, so you can still see where the card sits. The five property rows are now one line of chips pinned below the title, so status and assignee stay readable while you scroll the comments, and the description and comments are visible the moment the panel opens. On a new card, typing a title and pressing Enter creates it. The card's own page shows the same controls in a single panel where every row lines up — status through tags, then who filed the card and when, then Delete — instead of four blocks at three different indents with the ticket number repeated below the breadcrumb that already showed it. Clicking the number in the breadcrumb copies a link to the card.
- **The card panel's top line says whose card it is on the left and holds the controls on the right.** The ticket ID and author lead the line; stepping through the board, opening the card as a page and Close sit together at its end, with Close set apart so it no longer reads as one more thing you can do to the card. On a phone the author's name shortens instead of pushing the controls off the line. Status, assignee, priority, due date and tags share one line and wrap only when they run out of room — tags no longer take a line of their own on every card, and where the line does break they carry on beside whatever came before them.
- **Walk a board from inside a card.** With a card open, one control in the panel's top corner steps through the board: up and down for the previous and next card in the same column, left and right for the top of the column either side, with the board sliding across to follow. Between the up and down steppers it says where you are — 2/7 means the second of the seven cards your filters show in this column. Each button names its keyboard shortcut when you point at it, so `↑` `↓` `←` `→` do the same thing without reaching for the mouse, and a direction with nowhere to go is greyed out. Triaging a column, or reading through everything In Progress before a standup, no longer means closing and reopening a card for each one. Arrow keys still belong to whatever you are actually using: a description or comment you are typing in, an open status or priority menu, the date picker. Empty columns are skipped, and the ends of a column and of the board stop rather than wrapping around.
- **Opening a card brings its column to the front, and gives the card more room.** The panel opens over the right of the screen, which is where the column you were working in usually is — so the point of a side panel, seeing the board while you read a card, was lost on exactly the card you had just clicked. The board now slides that column to the left, into the same position the first column sits in when a board loads, and the panel takes the rest of the width: about a third wider than before on a laptop screen, so tables, code and attachments in a card have room to breathe. Descriptions and comments use that width, so a comment that took three lines now takes two. The card's content also sits further in from the panel's edges — the same gap the board keeps between the sidebar and its first column. Closing the card puts the board back exactly where you left it. On a window too narrow for both, the board stays put and the panel opens at its usual width.
- **Fixed: on a narrow window, a card's page opened on its properties instead of the card.** The side panel was ordered to the right of the content on wide screens only, so on a phone or a split window it stacked *above* everything — the first things on screen were the status dropdown and a Delete button, with the card's own title below them. The title leads at every width now.
- **Fixed: a long card title was unreadable.** The title was a single-line field, so anything past about seventy characters ran off the right edge with no ellipsis and no way to read the rest except arrowing through it. Titles now wrap onto as many lines as they need, on the card panel and the card's own page. Pressing Enter still saves rather than adding a line.
- **Small things on the card panel.** Its section headings were set at three different letter-spacings, and only two of them had icons. Content scrolling past the pinned header fades out instead of being sliced through the middle of a line of text. Comment edit and delete buttons stay out of the way until you reach the comment, matching attachments. Opening a card no longer puts the keyboard on "open as a full page", where pressing Enter left the board you had just opened the card from. And the `⌘↵` hint now rides on the button it triggers everywhere it appears, rather than floating next to it in some places and sitting inside it in others.
- **A card with nothing on it looks like a card with nothing on it.** Opening an empty card used to show three headings, two of them with nothing underneath, and a full markdown editor — tabs, a formatting toolbar, an AI button — sitting open and empty for a comment nobody was writing, directly below an identical one for the description. An empty card is now three single lines that each say what goes there and are each the button that puts it there: "Add a description…", "Add a file, or drop it here", "Leave a comment…". No heading appears over a section until there is something in it to count. The comment box also no longer asks you to "describe the task".
- **Save sits under the thing it saves.** A card's description is committed by a Save button directly beneath its editor, with `⌘↵` on it, and Cancel beside it — instead of a button at the far end of the panel that you reached past the attachments and every comment, and which sat greyed out on every card you were merely reading. Everything else on a card already saved itself, so the card panel has no button bar at all now and the card's own page has no Save in its sidebar — the height goes to the card. Deleting a card is on the card's own page, beside the timestamps and the author, and asks the same way the rest of the app does.
- **A description reads as text, and copies as text.** The heading over it is gone — it sits directly under the title, which is where the card's content belongs and needed no label saying so. Beside it are two buttons: Edit, and one that copies the description as Markdown, which is what you want when it is going into a commit message or a chat rather than back into Completo. Selecting part of a paragraph works the way selecting text anywhere works.
- **Editing a card field is instant, everywhere.** Changing a priority, status, assignee, due date or tag used to reload the entire board or list and re-animate every row; it now updates immediately, and reverts with an explanation if the server refuses. The card panel and card page no longer make you press Save for those fields either — the title saves as you finish typing it, and the description is the one thing left with a Save of its own. Leaving a card no longer warns you about a status change the server already accepted.
- **Every field that is a list opens the same menu.** Status, priority, assignee and tags each name the field at the top, put their dot, icon or face on one left edge and mark the current value the same way, whether you may pick one value or several — on the board, in a list and on the card alike. All of them take arrow keys and type-to-jump, and the status menu on a card shows status colours, which it previously didn't. They open in the same place too — below the control, lined up with the column of controls they belong to, and on a board card flush with the card's edge whichever field you picked. The due date stays a calendar, the one field that genuinely isn't a list, and it now carries the same header as the rest.
- **Switching between a project's views is a visible control.** The chevron beside the board or list name was invisible until you hovered it, and it was the only thing marking the name as clickable. It is now always there and says what it does. The menu behind it is the one the card fields use — headed, with the current view ticked on the right; it used to mark that view by *replacing its icon* with the tick and grey it out, so the view you were looking at was the one row that didn't say whether it was a board or a list, and looked unavailable into the bargain.
- **A comment thread reads as a conversation.** Every comment now sits in its own bounded record, separated by a hairline that starts where the text does — so the authors' faces hang outside it, down the left margin. Before, nothing marked where one comment ended: the author's name was set almost as large as the comment under it, so a name and a sentence looked alike and four comments ran together as eight loose lines, and a comment containing a code block was the worst case, because the block had a clear border while the comment holding it had none. Names are a quiet line above what they said, each with the author's face beside it in their own colour, comments are spaced evenly apart however they are written, and hovering a timestamp gives the exact date and time behind "2d ago" — three comments posted hours apart otherwise all read as "2d ago". The box for writing a new one sits clearly below the thread rather than at the same interval as one more comment.
- **Comments and descriptions stop changing size mid-sentence.** A mention is now exactly the size of the sentence it sits in — it used to be slightly smaller, which made every line carrying one ripple — and inline code takes one clear step down instead of a size no one chose. Code blocks were the worst of it: they were set two points smaller than intended, so a snippet was harder to read than the prose around it.
- **People have a colour.** Anyone without a profile picture used to appear as grey initials, so a thread with five people in it, a board with a dozen assignees, or a project's member list showed a row of identical grey discs — and on a comment thread, where the faces down the left edge are the only thing marking where one comment ends and the next begins, that made the thread hard to follow at a glance. Each person now gets a stable colour derived from their name, the same one everywhere they appear, and it is adjusted for whichever theme you are in.
- **A code block in a description or a comment has a copy button,** and says which language it is in. Selecting a snippet by hand inside a scrolling panel was the fiddliest copy on the card.
- **Fixed: dropping a file on a card could throw the card away.** Files could only be dropped on the attachments box; drop one on the description or the comments and the browser opened the file itself, leaving the page you were on. A file dropped anywhere on a card is now attached to it, and the card outlines to show it. The target is also there before you start dragging, rather than appearing under the cursor once the drag is already moving.
- **Removing an attachment asks first.** It was a single click on a small icon, with nothing to undo it — the only thing on a card that could be destroyed without a question. It now confirms in place, the way deleting a comment does.
- **Descriptions and comments you have typed are kept.** In-progress text — a description, a new comment, an edit to one of your own comments — is saved locally as you write, so closing a card by accident, reloading, or losing the tab no longer costs it. Reopening the card puts you back in the editor with the text and says where it came from, and one click discards it. A draft started in the side panel is waiting on the card's own page, since it is the same field of the same card. Because nothing can now be lost by closing, the card panel no longer stops you on the way out to ask.
- **List views open on the title, not the ID, and stop repeating what isn't there.** New lists and My Tasks put Title first and the ticket ID last; existing lists keep the column order you gave them. Every row used to say "Medium" and show an em-dash in each unset column — priority now only shows when it is High or Urgent, and empty cells stay blank until you hover the row, where the field is still there to click.
- **My Tasks is a list view like any other.** It can change a card's status and tags, which it couldn't before: the one screen built for working through your own queue was the one screen where you could not move a card to In Progress. Its "Fields" button works now too — it opened a dialog that did not exist — and it explains why it is empty, which is not obvious if you are an administrator who can see every project.
- **View settings is tabbed instead of one long scroll.** Columns and filters were stacked in a single column, so reordering a board meant scrolling past the filter section and setting a filter meant scrolling past the columns. Each tab shows a count — how many columns the view has, how many filters are active — which you previously had to scroll to the bottom to learn. Tag filtering is a searchable list rather than a chip for every tag in the project.
- **User management is a table.** Eighteen near-identical cards in a three-across grid meant reading all of them to find the one suspended account. Name, email, role, status and last seen are now columns, so each fact is in the same place on every row, and only the exceptions are marked. Actions moved to a row menu: the only way to suspend someone used to be clicking the word "User". Pending project invitations became a table on the same page.
- **Every tag, status and priority colour is legible, whichever one you pick.** A dark tag colour used to sit on a faint wash of itself and effectively disappear, and the same tag rendered at two different tints depending on the screen. Now the app keeps the hue you chose and decides the lightness itself, so a label meets the WCAG AA contrast minimum on all sixteen offered colours in both themes — including the deliberately dark ones, which no amount of tinting could previously rescue. Status dots and priority bars are held to the standard for graphical marks too; a slate-grey status dot on a dark screen was previously about half as visible as it needed to be. A tag you named "ux/ui" also no longer displays as "UX/UI".
- **The login, error and profile screens have real display type.** Nothing in the app was allowed to be larger than 20px, so a wordmark, a 404 headline and the count of cards assigned to you were all set at not-quite-heading size and read as scaled-up body text. They now use a proper display size in the app's monospace — the same face as ticket IDs and code — which suits all three, since two of them are a code and a number.
- **Project cards say what they are counting.** "12  1  6" behind four icons is now "12 cards · 6 people · 7m ago", and a project without a description no longer displays the words "No description". The project key is quiet metadata beside the name instead of a coloured chip competing with it.
- **Press `⌘K` (or `Ctrl+K`) to search.** Jump to any project or run a command without reaching for the sidebar. The sidebar itself now groups projects and admin pages under headings, can be resized, and keeps the theme switch reachable when collapsed.
- **Every page has a consistent header** with its title, its actions and the notification bell in the same place, and browser tabs finally show which page you are on.
- **Empty screens explain what goes there** and offer the action that fills them, instead of the five different treatments they had before. Boards and lists show a loading placeholder rather than appearing empty until data arrives.
- **Fixed: leaving a description edit displayed the unsaved text as though it had been saved.** Pressing Escape in the description editor closed it but kept what you had typed on screen, formatted exactly like a stored description — so there was nothing to tell you it had not been written down, and closing the card then discarded it without a word. Leaving the editor now shows what is actually saved, and what you typed is kept as a draft.
- **Fixed: `⌘↵` saved cards you hadn't changed.** Using the shortcut to dismiss a card you had only read still wrote to it and moved its "updated" time, which pushed it to the top of anything sorted by recent activity. The Save button had been correctly greyed out the whole time; the shortcut simply ignored it.
- **Fixed: list views could render every title blank.** With enough columns showing, the fixed-width ones took all the space and the Title column collapsed to a few pixels — its header overlapping its neighbour and not one row showing a title. It degraded with the width of your window, so it looked fine on a large screen. Title now has a floor and the table scrolls sideways instead, and where it does the last column fades out rather than ending in a hard cut — the only cue that there is more to the right. The same table was clipped at both edges, with the ID column hidden behind the sidebar divider and the assignee column running off the right.
- **Fixed: the Done checkbox in a list was a squashed rectangle.** The column was 36px wide and spent 24 of them on padding, leaving 12px of room for an 18px control, so it rendered as a lozenge on every row of every list — including My Tasks, where it is the first thing on the screen. It is a square again, and it has a hover state: it used to have one that set the border colour it already had.
- **Fixed: hovering a row's ticket ID slid two copy buttons over the next column.** They are positioned to the right of the ID and an 88px cell has no room for them, so they landed on the due date. Clicking the ID still copies its link, and both buttons are still there on the card itself, where there is space.
- **Fixed: uploaded profile pictures never appeared.** Avatars fell back to initials everywhere — the sidebar, list views, member lists — even for people who had one.
- **Fixed: the theme switch disappeared when the sidebar was collapsed**, leaving no way to change theme.
- **Fixed: every unknown URL said "Card not found."** A mistyped project link, a deleted board and `/nonsense` all claimed a card was missing. The message now names what was actually not found.
- **Accessibility:** icon-only buttons, columns and inline editors now have names screen readers can read; sortable table headers and the status, priority, assignee, tag and due-date editors in list views are reachable and operable by keyboard; dialogs announce their titles; and every animation respects "reduce motion".

### Dev

Nothing here changes what a user sees; all of it changes what a contributor can rely on.

- **The dark surface ramp is now overridden in `main.css`.** Nuxt UI's dark defaults map `--ui-bg-muted`, `--ui-bg-elevated` and `--ui-border` all to zinc-800 and both accented tokens to zinc-700 — six semantic tokens on three values, against light mode's five. Two consequences were measured rather than guessed: every board column's `border-default` drew itself in its own `bg-muted` colour, and `hover:bg-elevated` on a `bg-muted` surface was a 0-delta no-op in 27 files. `CLAUDE.md` had documented the collision and prescribed remembering it per call site; the ramp is repaired once instead, which gives the emphasis border back its job.
- **The raw-palette guard actually guards now.** Its regex was `(?:bg|text|border|divide)-(?:zinc|slate)-\d{2,3}` — four prefixes, four hardcoded variants — so **64 raw grey utilities were live and the test was green**, each one hand-maintaining the dark mode the test exists to prevent. Both allowlists are deleted rather than extended (a bare `zinc-400` in source can only be a palette reference), the neutral family is derived from `app.config.ts`, and the 64 sites are migrated: 30 `placeholder-zinc-*` pairs → `placeholder:text-dimmed`, plus `via-`, `ring-offset-`, `shadow-` and two `w-[304px]` → `w-column`. The "no arbitrary values" claim is now four separate assertions with a short, commented exemption list, because a guard that overstates its coverage is worse than one that admits it.
- **Design guard tests assert relationships, not class strings.** ~85% of `card-editors.test.ts` pinned literal Tailwind strings, so a redesign had to edit the test to change anything — and several assertions could not fail at all (`not.toContain('#ef4444')` banned a hex never in the list; `toMatch(/baseline/)` passed on a JSDoc line). Rewritten as properties: contrast recomputed from the percentages in `main.css`, the byline's type step compared to the body's through the scale, `UiFieldRow`'s geometry read once and compared, the composer's gap compared to the whole inter-comment interval. Each rewrite was falsified by breaking the source it guards.
- **The identity ramp is 13 hues and states its exclusion as a measured band.** `--ui-error` is at oklch hue 22.2°; `#f43f5e` sat 6.2° away while the comment claimed the error red was "deliberately absent". The rule is now "no hue within 15° of `--ui-error`" and the guard computes hue angles.
- **`CLAUDE.md` gained a standard for its own rules,** after an audit found ~17 provably false or overreaching entries — including a ban on keyboard navigation that `app/utils/board-nav.ts` has shipped for a while, a "gradient in exactly three places" budget where two of the three did not exist and twelve unnamed sites did, and `.swatch` certified as deriving a "readable" foreground while the filled tag pill measured 2.50:1 (fixed below). A rule must name the mechanism rather than the conclusion, its guard must recompute the property rather than restate the value, an unmeasured claim gets deleted rather than softened, and a reversal must be applied everywhere the old rationale is recorded.
- **Swatch colours set their lightness instead of mixing it.** `--swatch-fg` and friends are now `oklch(from var(--swatch) L c h)` — hue and chroma from the stored hex, lightness from `main.css` — rather than `color-mix(… N%, black)`. That is what makes the contrast figures above reachable at all: a mix's output lightness depends on its *input's*, so no pair of percentages could rescue `#334155`, and `COLOR_PALETTE` offers eight dark hexes on purpose. Measured before → after, worst case across every hex `COLOR_PALETTE` offers: light 2.50:1 → 5.68:1 text on its fill and 1.92:1 → 3.30:1 dot; dark 3.61:1 → 6.66:1 and 1.71:1 → 5.74:1. Text on the page is looser still at 6.18:1 light and 7.80:1 dark. `.swatch-avatar` moved onto the same mechanism, so the family has one recipe with per-member lightness rather than two sets of percentages. `--ui-bg` is now declared in the `.dark` ramp so the contrast assertion can derive the page colour instead of restating it.
- **The type ladder has a declared display tier:** `--text-2xl` 26 / `--text-3xl` 32 / `--text-4xl` 38, line-heights tightening 1.2 → 1.05, plus `--tracking-display` and a `--font-display` role pointing at JetBrains Mono. Everything above 20px was previously undeclared, so the two sites that reached for `text-2xl` got Tailwind's 1.5 leading and no tracking — which is why they read as scaled-up body text rather than as display. The tier is gated by mechanism, not by a file list: a display step needs a surface with nothing else on it, so it is banned on the board, lists, cards and the panel, and the guard fails if one appears there.

## v0.8.0 (2026-08-12)

### Upgrading

Two things to check before you deploy this one. Everything else is a straight upgrade.

- **Serving Completo over plain HTTP from an address other than `localhost`?** Set `NUXT_SESSION_COOKIE_SECURE=false`, or nobody will be able to sign in: the session cookie is now marked `Secure`, and browsers silently discard those on an insecure origin. `localhost` needs no change, and neither does HTTPS terminated at a reverse proxy — which covers most installs.
- **Migration `0004` stops the deploy if two accounts differ only in the capitalisation of their email.** It lowercases every address and adds a case-insensitive unique index, so a genuine pair — `foo@example.com` and `Foo@example.com` — has to be resolved by hand first, since only you can decide which identity keeps its cards and memberships. Check with `SELECT lower(email), count(*) FROM users GROUP BY lower(email) HAVING count(*) > 1`. No rows means nothing to do.

API clients: `mimeType` on an attachment is now derived from the file extension rather than echoing the uploader's declared type, and attachment downloads send `Content-Disposition: attachment` for everything except images, PDF and plain text.

### App
- **Cards now show who created them.** The card detail page has a "Created by" line next to the timestamps, the card modal credits the author next to the ticket ID, and list views (including My Tasks) can show a **Creator** column, sortable like Assignee. Creator is set once when the card is created and can't be changed. Cards whose creator has since been deleted show "Unknown". Existing cards already show the right person — the creator has been recorded since the first release, just never displayed, so no backfill is needed.
- **Fixed: sorting a list by Due Date wouldn't stick.** Clicking the Due Date header sorted the rows and then failed with "Invalid sort field" — the column was sortable in the table but the server refused to remember it, so the order reset on reload. Due Date now saves like every other sortable column.
- **Fixed: the Done checkbox column couldn't be picked when creating a list.** It was offered in a list's settings but missing from the create-view step, so you had to make the list first and add the column afterwards. Both pickers now offer the same set of columns.
- **Fixed: pressing `Esc` in a card editor closed the whole card and threw away what you'd typed.** It affected the comment box, a comment you were editing, and the card description — the keystroke was meant to be handled locally (cancel the edit, close the description editor) and it was, but it also travelled on and dismissed the card modal behind it. `Esc` now stops at the editor it was pressed in: it dismisses the `@mention` list if one is open, otherwise cancels a comment edit or closes the description editor, and does nothing at all when you're partway through a new comment. Closing the card another way — clicking outside, or the close button — now asks first when an editor is holding text, naming what's at risk, and hands focus back to where you left off if you choose to keep editing.
- **Fixed: using an AI skill on a comment, then pressing `Cmd+Enter`, closed the card and threw the comment away.** The shortcut is routed by which editor has focus, and the AI round-trip lost it: the skill menu took focus, then closed onto a button that had meanwhile been replaced by "Stop", leaving focus nowhere — so `Cmd+Enter` fell through to the card modal, which saved the card, closed, and took the unposted comment with it. Focus now stays inside the editor throughout: on the "Keep" button while you review the suggestion, and back in the text box once you keep or discard it. `Cmd+Enter` straight from the review state posts the comment as it stands.
- **Fixed: the icon list in project settings couldn't be scrolled, and opening it put Save out of reach.** Typing in the icon search matches against all ~1,770 Lucide names, so the grid grew to well over a hundred rows. In the edit dialog that pushed the bottom of the form — Key, Slug, Done status, and the Save, Cancel and Delete buttons — past the dialog's edge with nothing to scroll, so the only way out was to close the picker again. The icon grid now scrolls inside a fixed height, and the project form scrolls whenever it outgrows the dialog.

- **Fixed: an invited user who signed up on the register page instead of using their invitation link was left stranded.** For someone an admin had created an account for, registering returned "Account created. Please check your email" and then did nothing at all — no account, no email, and no way in, since their password had never been set. Registering with that address now re-sends their setup link instead. The response is deliberately unchanged, so it still reveals nothing about whether an address already has an account.
- **Fixed: signing in and signing up now ignore capitalisation in email addresses.** `Someone@example.com` and `someone@example.com` were treated as two different people: registering the second form when the first already existed created a *second* account, and each could then only be reached by typing that exact capitalisation. Password reset always lowercased, so a mixed-case account could never reset its password either. Addresses are now stored lowercased, matched case-insensitively everywhere, and the database enforces it.
- **Fixed: being invited and then signing in with Google, GitHub or Microsoft left the account marked "pending setup" forever.** The sign-in worked and the person could use Completo normally, but user management still listed them as never having set up, and password reset stayed blocked for them. Claiming an invitation through a social provider now completes the account.
- **The "restricted to approved email domains" message now tells invited people what to do.** Someone invited from a domain that isn't on the allowlist hits the same wall as an uninvited stranger, with no hint that their invitation email is the way in. The message now says so — to everyone who sees it, since wording it based on whether that address has an invitation would let anyone probe who has been invited.
- **Fixed: password recovery couldn't be completed in the browser.** "Forgot password?" and every emailed reset link redirected to the sign-in page — and the link's token was discarded on the way — so anyone locked out stayed locked out. Both pages were missing from the list of routes that load without a session. They also stay reachable while signed in, which is the only way back for someone who is still logged in somewhere but has forgotten the password they'd need to change it.
- **Security: an emailed link can no longer be redeemed for something it wasn't issued for.** Verification, password-reset and account-setup links all drew on one pool of tokens, and each page accepted any of them — so a "confirm your email address" link could be used to set a new password on that account, and the reply signed the sender straight in. Anyone who saw one such message (a forwarded mail, a shared or team inbox) could take the account over without knowing its password. Each link is now valid only for the flow that sent it. Setup links additionally refuse accounts that have already been set up, where they could previously overwrite a live user's password and display name.
- **Security: an uploaded file can no longer run as part of Completo.** Downloads echoed back the content type the uploading browser claimed, and showed the file inline, so a project member could upload an HTML file — or an SVG, or any name ending in `.md` while declaring itself HTML — and anyone who opened it ran the uploader's script inside the app, with that person's access to every project they can see. Downloads now determine the type from the file's extension, and only show images, PDFs and plain text inline; anything else downloads. Image previews on cards are unaffected.
- **Security: the session cookie is now marked `Secure`.** It was explicitly configured not to be, overriding a safe framework default, so every HTTPS install sent its session cookie over any plain-HTTP request that reached the same host — a stray `http://` link, a misconfigured proxy or a redirect was enough to leak it. If you reach Completo over plain HTTP from anything other than `localhost` — a home server at `http://192.168.1.50:3000`, say — set `NUXT_SESSION_COOKIE_SECURE=false`, or signing in will appear to work and drop you back at the login page. `localhost` needs no change (browsers treat it as a secure origin), and neither does TLS terminated at a reverse proxy. Existing sessions stay valid.
- **Fixed: adding a member by email failed on capitalisation.** Typing `Someone@Example.com` for an existing user created a pending invitation instead of adding them — and that invitation could never be accepted, because invitations are only picked up while registering. The address is now matched regardless of case or surrounding spaces.

### Dev
- **Migration `0004` lowercases existing email addresses and adds a case-insensitive unique index** (`users_email_lower_unique`). `users.email` was `UNIQUE` without `COLLATE NOCASE`, so normalising in code alone would leave the next endpoint free to reintroduce the split. The `UPDATE` runs against the old case-sensitive constraint on purpose: on an install that already holds both `foo@x` and `Foo@x`, it collides and the migration aborts rather than silently merging two identities — check with `SELECT lower(email), count(*) FROM users GROUP BY lower(email) HAVING count(*) > 1` and resolve those rows first.
- **Migration `0005` clears the stale "pending setup" badge from accounts that are already in use.** An invited account that was claimed through a social provider (or used via an API token) kept `!invited` and an unverified email, so user management listed active people as never having set up and `forgot-password` refused to help them. Rows carrying a `last_seen_at` are marked `!oauth` and dated from that sign-in; rows genuinely still awaiting setup are untouched. The code path that caused it is fixed too, so this is a one-off repair.
- **Issuing an account-setup link is now one helper**, `sendAccountSetupLink()` in `server/utils/account-setup.ts`, shared by admin user creation, the admin resend action, and the register path. It was duplicated token-for-token across the first two, which is why the third could not simply reuse it.
- **Migration `0006` adds `purpose` to `email_verification_tokens`** (`verify` / `reset` / `setup`), and `lookupVerificationToken()` now requires the caller to name the purpose it will accept. Hand-written: drizzle-kit emitted `ALTER TABLE ... ADD purpose text NOT NULL`, which SQLite rejects outright on a table holding any row, so this rebuilds the table instead — landing on exactly the shape the snapshot declares, rather than leaving behind a column default the snapshot doesn't describe. Existing rows are labelled by inference, which is sound because the three writers have mutually exclusive preconditions and each clears the user's other tokens first.
- **The public route list moved to `shared/utils/auth-routes.ts`** so it can be unit-tested; `auth.global.ts` can't be imported from a test because it calls `defineNuxtRouteMiddleware`. `tests/unit/auth-routes.test.ts` asserts that every page under `app/pages/auth/` appears in `PUBLIC_ROUTES` — the invariant that the recovery-page bug violated for as long as it existed, invisible to a suite that never mounts the client.
- **Attachment serving no longer trusts `attachments.mimeType`.** `serveContentType()` and `isInlineSafe()` in `server/utils/storage.ts` derive the response type from the filename, and uploads now store that derived value rather than the client's claim — leaving the raw claim in the database would keep a value there that is unsafe to echo, ready for the next endpoint to reach for. Note the upload allowlist can't be the defence here and isn't: its extension patterns match on filename alone and never inspect the declared type.
- **List column fields now live in one place**, `shared/utils/list-fields.ts`. They were spread across nine hardcoded arrays that never referenced each other — two server allowlists, two sortable-field sets, two picker option lists and three default-column lists — so adding a field meant six hand edits with nothing to catch a miss. Both bugs above were that drift. The pickers, validators, header labels and column widths now derive from a single declaration, `tests/unit/list-fields.test.ts` guards its invariants, and the sortable-fields integration test iterates the set instead of restating it (it had itself fallen two fields behind). Also closes a gap where `POST /api/projects/:id/lists` inserted `columns` unvalidated while the add-column endpoint checked the same input.
- **`nuxt.config.ts` now scans `shared/utils/*.ts` for icon names.** `icon.clientBundle.scan` globs templates only, so moving icon names into a `.ts` module dropped three from the bundle and they rendered as blanks — silently, since a missing icon isn't an error.

- **Fixed: default AI skills could never reach an existing installation.** `db-seed.ts` guarded its whole default-skills block with "does this table have any rows", so once an install had any skill, newly added defaults were skipped forever — even on a re-run. ## v0.6.7 (2026-08-05)

### App
- **Docker: zpinit now supervises the server instead of exec'ing it.** The image sets no `CMD`, which puts [zpinit](https://github.com/0ploy/zpinit) in supervise mode — it stays PID 1, so it reaps zombies for the container's whole lifetime and restarts the Nuxt server with capped-exponential backoff (1s→30s) if it crashes. Previously zpinit exec'd the server and exited, leaving no reaper and no in-container restarts. A readiness probe backs `zpctl ready`, and `zpctl status/restart/tail` now work (they were inert before).
  - Note: after 5 consecutive crashes the service is marked FATAL while the container still reports running. Use `zpctl ready` as a healthcheck if you need the container to fail loudly.
  - Passing a command to `docker run` still overrides this and runs that command once, so the ad-hoc CLI script invocations are unchanged.
- Docker: zpinit is pinned to `0.5.5` instead of `latest` for reproducible builds, and its config is validated at build time (`zpinit --check-config`) so a malformed service file fails the build rather than the deploy.
- **Fix: `pnpm setup` failed on a fresh clone.** `scripts/init-admin.sh` hardcoded `scripts/node_modules/.bin/tsx`, which only exists in the Docker image (`cd scripts && npm install`) and is gitignored otherwise — so the documented first-time bootstrap died at `db:init-admin` with `MODULE_NOT_FOUND`. It now runs `node scripts/user-create.ts` directly, like every other `db:*` / `user:*` script.
- Node 24 LTS and pnpm 11.17.0 are now pinned consistently across `package.json`, the prod image and the dev image. The prod runtime base moves from `alpine:3.23` to `alpine:3.24` (same Node 24.18.x, same native ABI).
- **`tsx` is gone — scripts run as `node scripts/foo.ts`.** Node strips TypeScript natively (default since 22.18), so the same command now works in dev, in prod, and on the host. Previously the prod entrypoint used a vendored tsx binary while dev used `pnpm db:*`, so the two paths differed for no good reason. `tsx` is dropped from `scripts/package.json`, shrinking the prod image by ~16MB (188MB → 172MB), and the runtime image now contains no package manager and no TS loader at all.
  - New `engines.node >= 22.18` in `package.json`. `scripts/*.ts` must stay within erasable syntax (no `enum`, `namespace`, parameter properties or decorators) and use no extension-less relative imports.
  - Ad-hoc invocations change accordingly: `docker exec <container> node scripts/user-create.ts …` (was `node ./scripts/node_modules/.bin/tsx scripts/user-create.ts …`).
- **README corrections.** The documented `SMTP_PORT` default was wrong (`587` — the code falls back to `1025`). The quickstart claimed Node alone was enough, but a fresh Node has no `pnpm` on PATH, so `corepack enable` is now an explicit step alongside the Node 22.18 floor. "All commands work with both `npm run` and `pnpm`" was true of the individual scripts but not `setup`, which chains via pnpm. `db:cleanup` was described as removing "expired sessions and soft-deleted data" — it touches neither; it drops orphaned rows and expired invites/tokens, prunes unused uploads, and VACUUMs.
- **README: new "Development environment (zdev)" section** documenting the containerised dev setup and its seeded logins.

### Dev
- Local dev environment migrated from `.scdev/` to `.zdev/` (the tool's current name and config format). Use `zdev start`; run `zdev update` — not `zdev restart` — after editing `.zdev/config.yaml`.
- **The dev container now boots via zpinit too**, from its own `.zdev/Dockerfile`. On every start it runs install → migrate → seed, then supervises the Nuxt dev server.
- **The dev container is built not to die**, so there's always something to debug. zpinit runs in supervise mode (stays PID 1, restarts the dev server with 1s→30s backoff) and `entrypoint_on_failure = "continue"`, so neither a crashed dev server nor a failed `pnpm install` takes the container down — the error stays in `zdev logs` and `zdev exec app sh` keeps working. `zpctl` is available inside the container (`zpctl status`, `zpctl restart app`, `zpctl tail -f app`).
- **Two fixed dev logins are seeded on every boot** and shown by `zdev info`: `admin@completo.local / admin1234` (admin) and `demo@completo.local / demo1234`. Both are created auto-verified. Dev-only — production still provisions from `ADMIN_USER_*`.
- Dev env wires the shared Mailpit (`SMTP_HOST: mail`), so invitation and verification mails are catchable via `zdev mail`. Because `isEmailEnabled()` keys off `SMTP_HOST`, dev logins require a verified email. `APP_URL` points at the routed HTTPS domain so links in those mails resolve.
- **The dev SQLite DB moved to `/app/data/sqlite.db` in a named volume**, out of the file sync (WAL files over Mutagen risk corruption). It is now the *only* dev database — previously, with no `DATABASE_URL` set, the container fell back to the relative `'sqlite.db'` default and silently shared the host's file. `*.db*` is also in `mutagen.ignore` so a host-side DB can't sync in and shadow it. Dev data is disposable by design: `zdev down -v -f` destroys the volume and the next `zdev start` reseeds from scratch.
- **Docs: `drizzle-kit push` is now documented as prohibited, not a dev shortcut.** Every schema change needs a committed migration. Two verified failure modes are recorded in `CLAUDE.md`: a `push`-built DB can never be migrated (`db:migrate` restarts at `0000` and dies on `table already exists`, which also breaks `pnpm setup`), and pushing then generating the matching migration still breaks the *next* migrate with `duplicate column name`.
- Boot applies committed migrations (`node scripts/db-migrate.ts`) rather than `drizzle-kit push`, which can prompt on destructive changes and would hang in the TTY-less boot.
- **New `zdev migrate` command** (`.zdev/commands/migrate.just`): `zdev migrate` applies pending migrations, plus `generate` (new SQL from schema changes), `seed` and `cleanup`. Each is a thin alias for the same command the container runs at boot. There is deliberately no `push` alias — see below.
- The dev image no longer installs anything with npm (the global `tsx` install is gone) — pnpm is the only package manager in it.
- `.zdev/local/` is gitignored for per-developer overrides (deep-merged onto the committed config).
